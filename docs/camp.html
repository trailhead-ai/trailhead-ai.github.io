Plugin

camp — multi-repo workspaces

One command opens a workspace spanning every repository in a group: a git worktree per repo, all on the same branch, provisioned, with its own tmux session to work in. One command tears it down.

A real feature rarely lives in one repository. It touches the API, the client, and the shared schema package, and those are three checkouts, three branches with three chances to name them differently, and three sets of bootstrap steps before anything runs. Doing that by hand is tedious for a person and error-prone for an agent — the most common failure is not a bad edit, it is an edit made in the wrong checkout, or on the wrong branch, or in a tree that was never bootstrapped.

camp makes that unit — the set of worktrees a single change spans — a first-class thing with a name. You declare a group once: the repositories you work on together. From then on camp new <slug> creates a git worktree in every member repo on a branch derived from the slug, runs whatever provisioning steps you configured, and hands your terminal to a tmux session rooted in the one directory that holds all of them. camp status answers “is it ready?”, camp attach takes you back to it later, camp stop ends its session, and camp remove takes the whole thing away.

camp is deliberately narrow about what it does not do. It never starts a harness conversation for you: a workspace’s session opens on a plain shell, and you run claude — or anything else — in whichever pane you like. It never resumes one on your behalf either; when a session comes back, each window tells you how to resume what it held and leaves the choice to you. And it never changes your shell’s directory on its own. That boundary is why camp is safe for an agent to call.

camp works without the other plugins and outside a harness session — it needs no lore vault and no craft ritual. It is not trailhead-free, though: the camp CLI locates a trailhead checkout by walking up from its own location, or via $TRAILHEAD_ROOT, and exits if it finds neither.

Key concepts

TermWhat it means
GroupA named set of repositories worked on together, declared in one TOML file. Each repository belongs to exactly one group — camp validates this and refuses to resolve a repo listed in two groups, naming both.
MemberOne repository in a group: a name, an absolute repo_root, an optional base branch (default origin/main), and optional named tasks.
WorkspaceThe whole multi-worktree unit for one slug — one directory holding a worktree per member, plus a manifest. Lives at state_dir("camp")/<group>/worktrees/<slug>/<member>.
SlugThe workspace’s name and address. Matches ^[a-z0-9-]+$; other input is normalized, with a notice on stderr. Path-traversal sequences and shell metacharacters are rejected outright, not normalized.
WorktreeOne member’s git worktree inside the workspace. A real checkout of that repo — git commands work normally in it.
Branch patternHow the slug becomes a branch name. Default worktree-{slug}, so slug login-rework gives branch worktree-login-rework in every member.
SessionThe workspace’s tmux session, named camp-<group>-<slug> and rooted at the workspace. Its windows and panes are ordinary tmux ones. A harness conversation started in any pane is recorded against the window it runs in, one per window, so a session that has died comes back with its windows and a resume line for each conversation.
TaskA named, multi-step provisioning unit referenced per member. Steps are argv lists (never a shell string) with {repo_root} / {worktree} / {workspace} / {slug} placeholders. Carries phase (provision, the default, or activate), required (default false), and timeout_seconds. Completion is recorded per member in the manifest, so a task that finished ok is never re-run — only failed and never-run tasks execute.
Harness profileOptional [harness] block: doc_files (the workspace doc to write, default CLAUDE.md), binary (harness binary name, default claude — only its basename is read; camp does not launch it), inject (claude-hook or stdout), and pretrust (pre-seed Claude Code’s per-directory trust flag, default true).
AccountOptional [launch] account key naming the harness account a group works under, such as ~/.claude-work. Every pane in the group’s sessions starts on it. Every declared account is also added to camp’s credential deny list, so no session window can be rooted in one.
HostAnother machine you declare in ~/.config/camp/hosts.toml. Workspace verbs that take --host <name> run the same command on that machine over SSH, and camp transfer moves a workspace to it.
DriftHow far a member’s branch has moved from its base: ahead and behind counts, and whether its upstream is gone, reported per member by camp status. Separately, camp doctor checks that the workspace manifest, git’s own worktree list, and the instance registry agree; see honest limits for the registry half.

Setting up a group

Group configs live at config_dir("camp")/groups/<name>.toml — on every platform including macOS that is ~/.config/camp/groups/<name>.toml. One file per group. You can write it by hand, but the CLI authors it for you:

$ camp group demo --member api=/Users/you/code/api --member web=/Users/you/code/web

That authors the config from the flags and wires the session hooks into each member repo. It refuses to overwrite an existing config unless you pass --force, and it verifies each repo_root exists and is a git repository unless you pass --allow-missing. camp group <name> --scaffold writes a commented stub for you to edit by hand instead (and wires no hooks); camp group <name> with no other flags re-wires hooks for a group that is already configured. camp groups lists every configured group and its members, from any directory.

An annotated config

This is trailhead’s own group config, trimmed. Everything past [group] and [[members]] is optional.

# ~/.config/camp/groups/trailhead.toml
[group]
name = "trailhead"

[[members]]
name = "trailhead"
repo_root = "/path/to/trailhead"
# Named tasks this member opts into, referenced by name.
tasks = ["code-review-graph"]

[[members]]
name = "trailhead-ai.github.io"
repo_root = "/path/to/trailhead-ai.github.io"

[[members]]
name = "outpost"
repo_root = "/path/to/outpost"

[branch]
# Slug 'login-rework' becomes branch 'worktree-login-rework'.
pattern = "worktree-{slug}"

# A group-level named task. Steps are argv lists, run with shell=False.
# phase:           "provision" (on worktree creation and each SessionStart
#                  reconcile) or "activate" (on first `camp activate`).
# required:        false means a failure warns in `camp status` and continues.
# timeout_seconds: per-step subprocess timeout.
[tasks.code-review-graph]
phase = "provision"
required = false
timeout_seconds = 180

[[tasks.code-review-graph.steps]]
name = "build"
cmd = ["code-review-graph", "build", "--repo", "{worktree}"]

# Optional. Omit it entirely and camp uses the claude defaults:
# doc_files = ["CLAUDE.md"], binary = "claude", inject = "claude-hook".
# [harness]
# doc_files = ["AGENTS.md"]   # Codex, Copilot, Cursor read this instead
# inject = "stdout"           # universal floor; any [harness] block
#                             # without an explicit inject defaults here
# pretrust = false            # claude launches only

Task steps, and every other command in a group config, are author-trusted local input. camp runs them as argv lists with no shell, but sharing group configs from authors you do not trust is explicitly out of scope.

The workspace lifecycle

Create or enter. camp new <slug> is the single entry point for both. If no manifest exists for that slug it creates the workspace — a worktree per member on the pattern branch — and provisions in the background; if one does exist it re-enters without re-provisioning or clobbering anything. Either way it then creates the workspace’s tmux session, or joins it if one is already running, and hands your terminal to it. --no-attach creates the session but leaves your terminal where it is; --no-session creates the workspace with no tmux session at all. The workspace’s absolute path is the only thing on stdout, so camp new composes in scripts.

Check it. camp status with a slug resolvable from cwd or --name prints the per-member provision state — pending, ready, or failed — and exits with a code an agent can branch on: 0 all ready, 2 some pending, 3 some failed. Run outside any workspace it prints the fleet-wide table of every workspace, its branch, and its members, and exits 0. camp list (alias ls) prints a table of workspaces with their session state and when each was last touched; --json gives the same for scripting.

Come back to it. camp attach <slug> hands your terminal to a workspace’s session — creating it if nothing is running, joining it if something is. With no slug it offers a numbered picker over the group’s workspaces. From inside tmux it switches your client rather than nesting, so hopping between workspaces never tears down the one you came from. If the session had died, attaching brings its windows back, and each window that held a conversation prints the harness command to resume it. camp stop <slug> previews what is running in the session’s windows, then kills the session; stopping a workspace that is already down is success.

Provision and activate. camp setup re-runs outstanding work for a workspace — pending or failed members and any task not yet recorded ok. camp activate <member> runs that member’s activate-phase tasks and surfaces its workspace doc (CLAUDE.md by default) as context for the current session. camp new --activate starts every member’s activate-phase work in the background once the workspace reaches boot-readiness; add --no-wait to skip that wait.

Work across members. camp foreach <cmd> runs a command in each member worktree with no shell interpretation, skipping members whose worktree is absent. --fail-fast stops at the first failure; --json gives a per-member result map.

Keep it current. camp sync fetches and fast-forwards each member’s canonical checkout to origin/main and is safe by default — a dirty or off-main repo is skipped, not reset, unless you pass --force. camp rebase [--onto <branch>] rebases each member’s workspace branch onto origin/main, or the branch you name, and names every member whose rebase failed.

Tear it down. camp remove (alias rm) removes the workspace and its worktrees. It refuses on a dirty tree, and refuses while a harness conversation rooted in the workspace could still be resumed, unless you pass --force. It leaves the workspace’s tmux session alone, so run camp stop first. Run from inside the workspace, it prints the first member’s repo root on success — the place your shell should land, since the directory it was standing in is gone. On any failure, including partial removal, stdout is empty and the exit is nonzero.

camp never moves your shell — the wrapper does

camp new and camp attach need no help: they hand your terminal to a tmux session already rooted in the workspace, so there is nowhere left to cd. camp remove is different. Run from inside the workspace, it deletes the directory your shell is standing in, prints where you should go instead, and stops. Acting on that answer needs a shell function, which is what the trailhead shellenv line installs:

$ eval "$(/path/to/trailhead/bin/trailhead shellenv)"
# add that to your shell profile — fish, zsh, and bash are all handled

The wrapper it defines intercepts camp remove and camp rm and changes into the group’s first-member repo that camp printed. Without it, camp remove still does its work and prints the path, but nothing takes you there — it adds a one-line tip on stderr pointing at the shellenv line. To go to a workspace from a plain shell without a session, cd "$(camp pwd <slug>)" works anywhere.

Working across machines

camp can drive workspaces on other machines you reach over SSH. Declare each one once, along with this machine’s own name:

# ~/.config/camp/hosts.toml
self_name = "sunrise"

[hosts.andromeda]
ssh = "andromeda.lan"
# Where camp lives on that machine; a plain ssh command rarely has it on PATH.
camp_bin = "/home/you/.local/state/trailhead/bin/camp"

camp new, camp attach, camp status, camp stop, and camp remove all take --host <name>. The group resolves on this machine — from --group, or from your current directory — and is forwarded by name, so the far side needs a group configured under the same name with its member repos already cloned. camp list --host <name> lists every group’s workspaces on one machine; camp list --all-hosts (-a) lists this group’s workspaces on every declared machine plus this one, and -ag widens that to every group.

camp transfer <slug> --to <peer> moves a workspace to a declared peer: its committed history, its working-tree content, and the conversations rooted in it, with ownership moving to the peer as the last step. --dry-run previews every check without moving anything. Each member declares an excluded list of regenerable paths such as node_modules — an empty list is a valid answer, but a member that declares nothing is refused by name. A failed transfer exits with a code that says whether ownership moved and whether re-running is safe; camp --help lists them.

camp env works with the dev environments running in Docker on this machine and on the hosts you opt in with an env_hosts list in hosts.toml. camp env ls lists them, camp env attach <name> puts one on this machine’s localhost at its standard ports, and camp env status and camp env detach show and end the attachment. An environment appears once its containers carry camp’s camp.env.group and camp.env.name labels.

Hooks camp writes into your repos

Wiring a group modifies files in your repositories, so it is worth knowing exactly what changes. camp group writes a SessionStart hook entry into each member repo’s .claude/settings.json, invoking camp’s own session-bootstrap handler. Each workspace additionally gets its own .claude/settings.json with a SessionStart hook that reports provision status, and — when the inject strategy is claude-hook — a PostToolUse hook that loads a member’s doc silently into context mid-session instead of dumping it to the log.

The writes go through a JSON load-and-dump, never string templating: unrelated keys are preserved, paths with spaces or quotes round-trip, and re-running adds no duplicate entries. The command is written as ${CAMP_BIN:-<absolute path>} so you can override the binary without editing settings files. The window-by-window conversation record is a separate hook that ships inside the camp plugin itself, not in your repos.

Command reference

Every command below is verified against camp --help and the CLI source. --group <name> works on any group-aware command to target a group from outside it; --dry-run (or CAMP_DRY_RUN=1) prints what camp would execute without running it. The verbs listed under working across machines also take --host <name>.

A worked example

Two repositories, one change spanning both.

# 1. Declare the group, once. Writes ~/.config/camp/groups/demo.toml
#    and wires the SessionStart hook into both repos.
$ camp group demo --member api=/Users/you/code/api --member web=/Users/you/code/web

# 2. Open a workspace. camp hands your terminal to its tmux session.
$ camp new login-rework
camp new: created workspace 'login-rework' — provisioning in the background
  check provisioning: camp status login-rework
  activates when ready, or run: camp activate login-rework
/Users/you/.local/state/camp/demo/worktrees/login-rework
created camp-demo-login-rework

# 3. You are in the session, at the workspace root. Both repos are
#    checked out on worktree-login-rework, side by side.
$ ls
api  web

# 4. Is it ready? Exits 0 all ready, 2 some pending, 3 some failed.
$ camp status

# 5. Work normally — start claude in any pane; these are ordinary git checkouts.
$ camp foreach git status --short

# 6. Stepping away? Detach from tmux, and come back to it later.
$ camp attach login-rework

# 7. Done. Stop the session, then remove the workspace. remove refuses
#    on a dirty tree or a resumable conversation without --force.
$ camp stop login-rework
$ camp remove --name login-rework

Honest limits

camp is in daily use, and these are the sharp edges worth knowing before you plan around it.

Sessions need tmux. Without it, camp new still creates the workspace and prints its path, with a warning that it could not reach a session, and camp attach refuses. camp new --no-session is the way to work without tmux on purpose.

Dev-environment orchestration is not camp’s job. camp env lists and forwards environments, but never starts, builds, or health-checks them. Provisioning a workspace is what you write into tasks, nothing more.

camp rebase leaves conflicts for you. A member whose rebase conflicts is named and left mid-rebase in its worktree; camp carries on with the rest and exits nonzero.

Registry-drift detection is a placeholder. Nothing writes the instance registry, so camp doctor’s registry consistency check always reports no drift. The manifest and git-worktree halves of that check are real.

Host names are trusted, not checked. Every machine a transfer runs between must declare its own, different self_name. Two machines sharing a name pass every ownership check on both sides, and nothing catches it for you.

Claude Code is the only harness implemented. Harness profiles do support AGENTS.md-style doc files and a stdout injection floor that works with any tool, but the session hooks, conversation recording, and the trust pre-seed are Claude Code integrations.
