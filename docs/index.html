Documentation

Trailhead docs

Trailhead is scaffolding for agent-native development: durable memory, multi-repo workspaces, and an engineering process your coding agent actually follows. It installs into the agent harness you already use.

Everything here is local-first and plain text. There is no service to sign up for and no MCP server — the agent works through command-line tools over your shell, and state lives in git repositories and files on your own disk. Search runs off a local index that is derived from those files and can be rebuilt from them at any time.

How the pieces fit

Trailhead is one management CLI plus five agent-plugins. The CLI composes the plugins you select and wires them into your harness; the plugins are what your agent actually uses. They map onto the things a coding model does not have on its own:

PluginCoversWhat it gives the agent
loreMemoryA git-backed vault of decisions, lessons, tasks, and session notes it can search and add to
campEnvironmentOne workspace spanning every repo in a group, on matching branches, provisioned and ready
craftProcessRituals for shaping, planning, building test-first, and reviewing — run by specialist subagents
portageShippingLinked pull requests treated as one release: pushed, watched, triaged, merged in order
outpostReviewA local web cockpit where you review the agent's work and it picks your comments back up

The organizing idea underneath all of them is the group: a named set of repositories worked on together. Memory is scoped to the group, a workspace spans the group, and a release ships the group as one unit. If you only ever work in a single repository, a group of one works fine — but the design assumes real products span several.

They are independent on purpose

Nothing here is all-or-nothing. You can install a single plugin, or a single skill within a plugin. Common paths:

  • Just memory. Install lore alone and keep whatever workflow you already like. It has no dependency on the others.
  • Memory and workspaces. Add camp when a change starts spanning more than one repository.
  • The full loop. Add craft for process and portage for shipping once you want the agent running the whole arc of a change.

craft is never a dependency of the others. lore, camp, and portage each ship a command-line tool; craft and outpost are skills and subagents only.

What you need

  • Python 3.11 or newer. No third-party packages — the standard library is the whole runtime dependency set. Your system python3 may be older than 3.11; check before you start.
  • git, and a shell (bash, zsh, or fish).
  • An agent harness. Claude Code is what ships today.
  • The GitHub CLI (gh), authenticated — only if you want portage to open and merge pull requests.

Scope and honest limits

Trailhead is version 0.1.0 and in daily use building real products, but it is young. Worth knowing before you plan around it:

Claude Code is the only harness implemented. The architecture is harness-neutral — every capability wires through a single interface, and adding a harness requires no changes to the shared install path — but Codex, Cursor, and others are an extension point today, not shipped support.

GitHub is the only code host implemented. This affects portage only; the rest of the suite just needs git.

Memory recall is pull-based. The agent searches the vault when it decides to. There is no hook that automatically injects relevant memory into a conversation.

outpost needs a companion application that is not yet publicly released. Read the outpost page before counting on it.
